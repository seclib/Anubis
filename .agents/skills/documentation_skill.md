# Documentation Skill

## Context
Use this skill when changes, architecture, commands, APIs, or operational workflows need to be documented for future maintainers.

## Procedure
1. Identify the documented surface: feature, API, workflow, command, or architecture.
2. Read the relevant code or existing docs before writing.
3. Explain behavior, inputs, outputs, and constraints.
4. Include verification commands or operational notes when useful.
5. Keep docs accurate, scoped, and free of unrelated narrative.

## Expected Output
- Updated documentation
- Accurate technical details
- Usage or verification notes
- Links to relevant files or commands
