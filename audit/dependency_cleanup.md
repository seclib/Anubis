# ANUBIS Dependency Cleanup Audit

Audit date: 2026-06-05

## Executive Summary

ANUBIS has an unusually clean dependency surface:

- Python runtime dependencies: none.
- Python optional dev dependencies: `pytest`, `pytest-asyncio`, `ruff`.
- Node dependencies: none found.
- Rust dependencies: none found.

No dependency uninstall is recommended from the repository because there are no runtime packages to remove and the optional dev packages are not installed in the current environment. The only concrete local disk cleanup opportunity is generated cache/bytecode data.

## Migration Recommendations

1. Keep runtime dependencies empty.
2. Keep dev dependencies in `pyproject.toml` optional extras.
3. Decide whether `requirements.txt` should remain as a documentation/policy file. If retained, keep it comment-only.
4. Remove generated caches and bytecode from version control in a dedicated cleanup change.
5. Add ignore rules for `__pycache__/`, `*.pyc`, `.ruff_cache/`, `.pytest_cache/`, `node_modules/`, `target/`, and local virtualenvs if not already present.
6. If full pytest execution becomes canonical, install dev extras in CI or update the custom runner so `test_orchestrator.py` is no longer skipped.
7. Do not introduce Node or Rust dependency files until there is a real Node/Rust component.

## Final Assessment

There is no dependency bloat to remove from ANUBIS. The project is already dependency-minimal. The best cleanup is repository hygiene, not package removal: stop tracking generated Python bytecode and tool caches, keep dev tools optional, and avoid introducing Node/Rust ecosystems until they are needed.
